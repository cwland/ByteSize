# ByteSize iOS — Round I1 (Foundation) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An installable ByteSize iPhone app that signs in to a ByteSize server (password + emailed reset code), keeps the
login in the Keychain, and shows the five-slot tab bar, the radial (+) menu and the Profile sheet in the web app's themes.

**Architecture:** `ios/` in the ByteSize repo. All logic lives in the `ByteSizeKit` Swift package (tested with `swift test`
in seconds); the `ByteSize` app target holds SwiftUI views only. The Xcode project is generated by XcodeGen from
`ios/project.yml`. Theme colors are generated from `frontend/src/themes.ts` so the phone and web can't drift.

**Tech Stack:** Swift 6 (language mode 6), SwiftUI, Observation (`@Observable`), XCTest/XCUITest, XcodeGen, Node/tsx for the
theme generator, Vitest for the parity test.

**Spec:** `docs/superpowers/specs/2026-11-19-bytesize-ios-design.md` (§6.1–6.4, §6.10 "I1").

## Global Constraints

- Deployment target **iOS 17.0**; `ByteSizeKit` platforms `.iOS(.v17), .macOS(.v14)` (macOS only so `swift test` runs on the Mac).
- No third-party Swift packages. The app talks **only** to the user's ByteSize server.
- Bundle id `com.cwland.bytesize`; URL scheme `bytesize` (used in I6). Team id comes from git-ignored `ios/Local.xcconfig`
  (`DEVELOPMENT_TEAM = …`); simulator builds work without it.
- Login token only in the Keychain (service `com.cwland.bytesize`, account `login-token`). Server address in `UserDefaults`
  key `serverAddress`.
- Server error bodies are `{ "error": string, "details"?: [{ path, message }] }`; a 401 means signed out.
- Sign-in is by **username** (server field `username`), not email. Reset is by email + 6-digit code.
- Copy fixed by the spec: "Goals and targets are managed in the ByteSize web app." is for Goals (I4); Profile note:
  "Account and goals are set up in the ByteSize web app."; signed-out notice: "You were signed out".
- Every icon-only control has an `accessibilityLabel`.
- Builds and tests run on Cory's MacBook Pro via n8n workflow "Claude – MacBook Pro Command Runner"
  (id `r11URbU8ZfjNHbjz`): set the Run Command node's command, execute, read stdout. Checkout lives at
  `~/Developer/ByteSize`; prefix commands with `export PATH=/opt/homebrew/bin:/usr/local/bin:$PATH;`.
  Simulator destination: `platform=iOS Simulator,name=iPhone 17,OS=26.3` (use `xcrun simctl list devices available` to
  pick the first iPhone if that name is missing).

Server: **no server change is needed in I1** — `GET /api/auth/status` already returns
`{ setupRequired, passwords, forgotPassword, oauth: { label } | null }` and `GET /api/health` returns `{ ok, db, version }`.
(Spec §6.7 change 2 is therefore already satisfied; passkey availability is added to it in I6.)

## Review Focus

1. **Server address typed loosely** (`bytesize.example.com`, `https://x.com/`, `http://192.168.1.5:4100`, a pasted web URL
   with `/#/`) → normalized to scheme+host+port; a bare host gets `https://`. Pinned in Task 1.
2. **Token expired / revoked on the web ("sign out everywhere", password change)** → the next call returns 401, the app
   drops to Sign-in with "You were signed out", token removed. Pinned in Task 4.
3. **Server unreachable or not a ByteSize server** (wrong address, captive Wi-Fi returning HTML) → "Can't reach ByteSize at
   <host>" rather than a decoding crash. Pinned in Tasks 3 and 5.
4. **Validation error with details** (400 `Invalid request` + details) → the first detail's message is shown, not
   "Invalid request". Pinned in Task 3.
5. **Sign out while offline** → still signs out locally (token cleared), no error shown. Pinned in Task 4.
