# ByteSize M2b-2 — Week strip, AI services, food search — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A week strip replaces the date bar, AI services get Validate + recommended models + collapse + drag order, and food search forgives typos and puts basic foods first.

**Architecture:** Three independent slices (A+B week strip, C AI services, D search) on branch `m2b2`; A is backend for B. Each slice ships its own tests; only A adds a migration (0005).

**Tech Stack:** Fastify 5, Drizzle, Postgres 16 (pg_trgm already enabled), zod, Vitest; React 18, Vite 6, Tailwind 4, Testing Library.

**Spec:** `docs/superpowers/specs/2026-11-16-bytesize-m1-m2-design.md` §11

## Global Constraints

- Every user-owned query filters by the caller's `user_id`; new routes get the user only via `requireUser` / `requireAdmin`; new user-owned data is covered by `isolation.test.ts`.
- No new npm dependencies (drag, scroll-snap and fuzzy matching are built with what's there).
- Week start: integer 0–6 (0 = Sunday), default 0, stored in `user_settings.week_start`, sent as `weekStart` in `/api/settings/me`.
- Copy: "Week starts on", "Validate", "Key works · N models", "Recommended", "All models", "Basic foods", "Did you mean {word}?".
- Recommended models: at most 2 per provider; Home AI ("local") gets none.
- "Did you mean" shows only when the search returned fewer than 3 foods in total.
- UI copy plain English; tests RED→GREEN for every behavior.

## Review Focus

1. A week start other than Sunday (e.g. Monday) must still show 7 consecutive days and put today in the right column.
2. Days with only water entries get no dot; another user's entries never give a dot.
3. Model names with dates/versions ("claude-haiku-4-5-20251001", "gemini-2.5-flash-lite", "gpt-5-mini") must sort newest first within a family; preview/embedding/audio/tts models are never recommended.
4. Dragging a service must save the new order exactly as shown; a service being dragged can't be dropped outside the list.
5. A query with no close spelling (or one already spelled right) never shows "Did you mean".
