# ByteSize M2b-3 — Photo upload, recipes, quick meals, My Foods — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Read a barcode or nutrition label from a photo into a food; build recipes and quick meals; manage them all in My Foods.

**Architecture:** Two backend tasks (A photos, B recipes/quick meals) run in parallel; two frontend tasks (C photo UI on A, D My Foods/recipes/meals UI on B) follow in parallel. A owns migration 0006; B's migration is generated last and renumbered 0007 by the controller at merge (B must keep its schema change in one migration).

**Tech Stack:** Fastify 5, @fastify/multipart (installed, not registered), sharp (installed), zxing-wasm (new), Drizzle + Postgres 16, zod, Vitest; React 18, Vite 6, Tailwind 4, Testing Library.

**Spec:** `docs/superpowers/specs/2026-11-16-bytesize-m1-m2-design.md` §12 (including "Settled after the builder check"), with 6.3 and 6.6a.

## Global Constraints

- Every user-owned row has `user_id`; every query filters by the caller; new routes get the user only via `requireUser`/`requireAdmin`; new user-owned data (uploads, recipe_items via user_foods, group_ref entries) is covered in `isolation.test.ts`.
- Photos: 12 MB per image, at most 2 images, request cap 25 MB; normalised with sharp (auto-rotate, max 1600 px longest side, JPEG); stored under `<DATA_DIR or data/app>/uploads/<user_id>/`; served only to their owner (`GET /api/photos/:id`, 404 for anyone else); unlinked uploads deleted after 24 h by an in-process cleanup (on start + hourly).
- Nothing from a photo is saved without the person tapping Save; AI-read fields are marked AI-estimated.
- Unknown nutrients stay unknown (absent), never 0 — in recipes and quick meals too.
- Copy: "Photo", "Read a label", "Add an AI service that reads photos to read labels", "Save as a meal", "Left out: …", "My Foods", "New food", "New recipe", "New quick meal", "Recalculate", "Recipe", "Meal", "Choose an amount this food can be measured in".
- No other new npm dependencies besides zxing-wasm (and only a pure-JS fallback decoder if zxing-wasm can't run on node:22-alpine — record it).
- Tests RED→GREEN for every behavior; stage files explicitly.

## Review Focus

1. Another user's photo id (or a made-up one) is never served or linkable — 404, and `photoId` from another user is rejected on save.
2. An iPhone photo (EXIF-rotated JPEG; HEIC if the browser sends it) either works or says plainly why ("Use a JPEG or PNG photo"); a non-image or oversize file is a clear 400/413, never a crash.
3. A recipe or quick meal with an ingredient whose nutrient is unknown shows that nutrient unknown, not 0; servings ÷ count math is exact for "6 servings of 350 g" (logging 300 g = 300/350 of a serving).
4. A quick meal whose item food was archived or deleted still logs that item from its snapshot; logging a quick meal makes one adjustable entry per item, and Recently tracked shows the meal once.
5. "Save as a meal" from a meal containing water or a vanished food leaves those out and lists them; the saved meal's portions equal the logged portions.

### Task A: Photos backend

**Files:** create `backend/src/lib/photos.ts`, `backend/src/routes/photos.ts`, `backend/tests/photos.test.ts`, test fixture images under `backend/tests/fixtures/` (a barcode PNG generated in the test or committed small, a label JPEG); modify `backend/src/app.ts` (register multipart + route + cleanup), `backend/src/db/schema.ts` (`uploads` table: id uuid pk, user_id, path, created_at, linked_at nullable; `user_foods.image_path` text), `backend/src/routes/my-foods.ts` + `backend/src/lib/foods.ts` (`photoId` on create/update links the upload; user foods' `imageUrl` = `/api/photos/<id>`), `backend/src/lib/ai.ts` (label extraction prompt on task "photo"), `backend/tests/isolation.test.ts`; migration `0006_photos` via `npx drizzle-kit generate --name photos`.

**Interfaces (produces):**
- `POST /api/photos/analyze` multipart (`images` 1–2 files, `mode` auto|barcode|label) → `{ photoIds: string[], barcode?: string, food?: FoodResult, draft?: FoodDraft & { photoId: string, barcode?: string }, errors: SourceError[], labelReading: boolean }` (`labelReading` false when no AI service has photos on).
- `GET /api/photos/:id` → image/jpeg (owner only).
- `POST /api/my-foods` and `PUT /api/my-foods/:id` accept optional `photoId` (must be the caller's unlinked or same-food upload, else 400 "That photo isn't available").
- `GET /api/ai/status` includes `photos: boolean`.

### Task B: Recipes and quick meals backend

**Files:** create `backend/src/lib/recipes.ts`, `backend/tests/recipes.test.ts`, `backend/tests/quick-meals.test.ts`; modify `schema.ts` (`recipe_items`: id, recipe_id → user_foods cascade, position, food_kind, food_id, quantity, unit, serving_index, fraction, snapshot jsonb {name, nutrients}; `user_foods.recipe_servings` double, `user_foods.serving_grams` double; `log_entries.group_ref` text), `routes/my-foods.ts`, `routes/log.ts`, `lib/foods.ts` (`foodKind` on FoodResult, recipes/meals in "My foods" group), `isolation.test.ts`. Migration: one file, `npx drizzle-kit generate --name recipes` (controller renumbers at merge).

**Interfaces (produces):**
- `POST/PUT /api/my-foods/recipes(/:id)` body `{ name, items: Item[], servings: number, servingGrams?: number, notes? }`; `Item = { food: {kind, id}, servingIndex, unit, quantity, fraction }` → `{ food: FoodResult & { items: ItemView[] } }`; `POST /api/my-foods/:id/recalculate`.
- `POST/PUT /api/my-foods/meals(/:id)` body `{ name, items: Item[] }`; `POST /api/my-foods/meals/from-entries` `{ name, ids: number[] }` → `{ food, leftOut: string[] }`.
- `GET /api/my-foods/:id` returns items for recipes/meals.
- `GET /api/my-foods?kind=all|foods|recipes|meals&sort=recent|used|az&q=`.
- `POST /api/log/meal` `{ day, meal, foodId, items?: Item[] (adjusted) }` → `{ entries }` (one per item, `group_ref = quick:<id>`, snapshot fallback for archived/missing foods).
- `GET /api/foods/recent?meal=` returns a quick meal once (kind quick_meal) for a group_ref use.
- `DELETE /api/my-foods/:id`: hard delete when never logged and not used as an item; else archive.
- `FoodResult.foodKind: 'custom'|'override'|'recipe'|'quick_meal'`.
